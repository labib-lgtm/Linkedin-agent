# Lynx Media Brand Guidelines

This skill is the source of truth for the Lynx Media look and voice. Anything Claude generates in this repo — images, carousel slides, lead-magnet PDFs, webapp UI, LinkedIn post copy — must conform to the rules below.

Lynx Media is an Amazon PPC agency for operators who already manage real spend. The brand reads confident, specific, and operator-grade — never student-tier or generic.

---

## Color Palette

### Core (use these by default)

| Token        | Hex        | Use                                                      |
|--------------|------------|----------------------------------------------------------|
| Lynx Green   | `#C6F21F`  | Primary accent. Hook highlights, CTA buttons, key stats. |
| Charcoal     | `#1C1C1C`  | Primary text. Dark backgrounds. Body copy on light bg.   |
| Light Gray   | `#F5F5F5`  | Page backgrounds, slide canvases, subtle fills.          |
| White        | `#FFFFFF`  | Card surfaces, text on Charcoal.                         |

### Supporting neutrals

| Token         | Hex        | Use                                          |
|---------------|------------|----------------------------------------------|
| Border Gray   | `#E5E5E5`  | Card borders, table dividers, subtle strokes.|
| Muted Text    | `#6B6B6B`  | Secondary copy, captions, metadata.          |

### Rules

- **One accent only.** Lynx Green is the single accent color. Do not introduce orange, blue, red, purple, or any other accent. If a chart needs multiple series, use shades of Charcoal/gray and reserve green for the highlighted series.
- **Charcoal on Light Gray** is the default reading combination. Use Charcoal-on-white for highest contrast (e.g., body slides).
- **Lynx Green on Charcoal** is the highest-impact pairing — reserve for hooks, headline stats, primary CTAs.
- Never put green text on a white background larger than ~18pt — it's hard to read. Green works as a *block* (highlighted background behind dark text) or as a large display element.

## Typography

| Role     | Family    | Weights used        | Fallback     |
|----------|-----------|---------------------|--------------|
| Headings | Montserrat| Bold, SemiBold, Medium | Arial, sans-serif |
| Body     | Inter     | Regular, Medium, SemiBold | Helvetica, sans-serif |
| Mono     | JetBrains Mono / system mono | Regular | Menlo, monospace |

### Rules

- Headings: Montserrat. Body: Inter. No exceptions.
- Tight letter-spacing on headings (`tracking-tight` in Tailwind, `-0.01em` to `-0.02em` in CSS). Inter body stays at default tracking.
- Avoid italics in headings. Italics in body only for genuine emphasis or quoted material.
- Numerals are part of the brand — when a stat is the focus (e.g., "$29M+ managed"), set it large in Montserrat Bold and let it carry the composition.

## Voice Rules (LinkedIn copy + any on-asset text)

These are non-negotiable. They apply to post bodies, hooks, carousel text, lead-magnet copy, and any string the system writes for human consumption.

- **No em-dashes (—).** Use periods or commas. AI-generated em-dashes are an immediate tell.
- **No asterisks (`*` or `**`).** LinkedIn doesn't render markdown; asterisks read as literal noise.
- **No hash characters (`#`).** No hashtags in post bodies. Operators don't tag.
- **No emoji** unless the user explicitly asks for one.
- **Specifics over generics.** "Cut TACoS from 18% to 11% in 6 weeks" beats "improved efficiency." Numbers, timeframes, dollar amounts, named tactics.
- **Operator vocabulary.** ACoS, TACoS, SP/SB/SD, search-term reports, dayparting, negative phrase, bid floors. Don't define these terms — the audience already knows them.
- **No filler openers.** Skip "In today's fast-paced world," "I want to share," "Here's something interesting." Open on the claim or the number.

## Image Assets (single-image posts)

Generated by `tools/gen_image_render.py` via OpenRouter. The asset must be **publish-ready**: no overlay step happens after rendering.

- All on-image text, stats, callouts must be baked into the render. Never produce a background-only image expecting later text overlay.
- Aspect ratio comes from the angle's `image_size` field (square 1:1, portrait 4:5, or landscape 1.91:1). Do not deviate.
- Color usage: Charcoal background OR Light Gray background. Lynx Green for the headline stat or one focal element.
- No Lynx logo on image assets. The post body identifies the author; logos on every asset reads spammy.
- Typography in renders: Montserrat for headlines, Inter for any supporting text. If the renderer can't access these fonts, fall back to Arial/Helvetica respectively — never use a serif or display font.

## Carousel Slides

Generated by `tools/gen_carousel_render.py` (Pillow). LinkedIn carousels are 1080x1350 PNG.

- **Cover slide:** Charcoal background. Hook text in white Montserrat Bold, with the most important phrase or number set on a Lynx Green block (green background, Charcoal text, ~12px padding). 64-96pt for the hook.
- **Body slides:** White or Light Gray background. Charcoal Montserrat Bold heading at top (~48-56pt). Inter Medium body (~28-32pt). Use Lynx Green sparingly to highlight the one number or term that matters per slide.
- **Closing CTA slide:** Charcoal background, Lynx Green CTA text or button-shape, white supporting copy. Echo the post's CTA keyword exactly.
- Slide count: 6-10. Anything longer than 10 loses retention.

## Lead-Magnet PDFs

Generated by `tools/gen_lead_magnet.py`. Letter portrait, 1275x1650 px (150 DPI).

- Cover page: Charcoal background, Lynx Green title bar, white subtitle. Title in Montserrat Bold 96-120pt. Subtitle in Inter Medium 32-40pt.
- Interior pages: White background, Charcoal text. Section headings in Montserrat Bold 48pt with a short Lynx Green underline (4-6px tall, ~80px wide). Body in Inter Regular 28-32pt with generous line-height (1.5).
- No page numbers on the cover. Page numbers on interior pages bottom-center, Inter Regular 18pt, muted gray.
- Closing page: Charcoal background, Lynx Green "Next step" block with the offer (DM keyword, calendar link, etc.).
- File size target: under 5 MB. Compress images before embedding.

## Webapp UI (Next.js + Tailwind)

The webapp at `webapp/` already has these tokens wired into `tailwind.config.ts`. Use them; don't introduce new color values inline.

| Tailwind class       | Hex        | Notes                                      |
|----------------------|------------|--------------------------------------------|
| `bg-lynx-green`      | `#C6F21F`  | Highlight blocks, primary CTAs.            |
| `text-lynx-charcoal` | `#1C1C1C`  | Default body text.                         |
| `bg-lynx-charcoal`   | `#1C1C1C`  | Header bar, dark sections.                 |
| `bg-muted` / `bg-card` | `#F5F5F5` / `#FFFFFF` | Page and card surfaces.    |
| `font-heading`       | Montserrat | Apply to all headings.                     |
| `font-sans` (default)| Inter      | Body text default.                         |

- Buttons: `variant="accent"` is the Lynx Green primary CTA. `variant="outline"` for secondary. Avoid `variant="default"` (gray) for primary actions.
- Status pills: keep using the existing `StatusBadge` component. Don't reinvent status colors.
- Tables: Charcoal text on white rows, Border Gray dividers, Muted Text for column headers.

## How Other Skills Should Use This

When `canvas-design`, `frontend-design`, `pptx`, `pdf`, or `docx` is invoked from inside this repo:

1. **Read this file first** before picking colors or fonts.
2. **Override the skill's defaults** with the Lynx palette and Montserrat/Inter pairing.
3. **Apply the voice rules** to any text the skill generates (no em-dashes, no asterisks, no hashtags).
4. **Match the asset type's rules** (image / carousel / PDF / webapp) above rather than the generic skill defaults.

If a skill's default brand template conflicts with these guidelines, the Lynx guidelines win every time inside this repo.
